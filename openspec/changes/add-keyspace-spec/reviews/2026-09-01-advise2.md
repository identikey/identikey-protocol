Accept-with-nits. The send-back boxes are closed in design and deltas.

## Steelman against

Send-back again: Requirement “Admin field on roster” rejects any
`join` whose actor is not *currently* `admin: true`, but outer genesis
*is* a `join` with no prior roster. That is a real contradiction.

It does not reopen architecture. Genesis is named (first admin join).
The missing sentence is the verify exception: the genesis join is valid
iff the actor appears as `admin: true` in **that same body**. `act`
writes it. Another send-back would delay the standards file for one
rule that the genesis pick already implies.

## One real tradeoff

First `join` as genesis (picked) vs an eighth `keyspace.genesis` kind.
The pick keeps the seven-kind freeze and makes an empty keyspace
impossible. The cost is the genesis verify exception above. Still the
right pick.

## Findings

Send-back items, closed:

1. Outer genesis = first `keyspace.join` with admin+PTK; inner =
   `keyspace.nest`; no eighth kind.
   (`design.md` 35–40; `specs/identikey-keyspace/spec.md` 23–44)
2. identikey-log `Op.actor` stays Ed25519
   (`crates/identikey-log/src/op.rs:12-13`;
   `crates/identikey-log/src/sign.rs:39`). P-256 is wrap-target only.
   (`design.md` 49–53; spec Requirement: Log actor vs wrap target)
3. Roster `admin` boolean; only current admins append administering
   kinds. (`design.md` 55–59; spec Requirement: Admin field on roster)

No new architecture holes that `act` would have to invent.

## What is solid

- Protocol word `keyspace`, product word `guild`. No `guild.*`.
- Distributed object; log is transport; Postgres is a cache.
- Seven kinds; `leave` distinct; kick/wrap/admin-grant are not kinds.
- Self-describing CBOR wrap; no HPKE; no PQ wrap this landing.
- Device cascade named, not specified as objects.
- Two profiles; access-node nested after assign-node.
- Three layers uncollapsed; capability-v1 not modified.
- Living file `docs/standards/identikey-keyspace-v1.md`. No
  `openspec/specs/` tree. Hooks, not filled fixtures.
- `content_hash` matches the log: `blake3` of canonical unsigned
  envelope bytes, no domain separation
  (`crates/identikey-log/src/codec.rs:190-202`).

## Implementer gaps (nits — `act` writes, do not amend here)

- Genesis `join` authorizes from its own body: actor must appear as
  `admin: true` in that join. Later ops check the applied roster.
- Wrap CBOR map keys (alg, recipient, ciphertext, nonce/epoch).
- RFC 7748 Ed25519→X25519 conversion (clamping, small-order points).
- Concurrent `epoch-begin`: log does not merge; spec the conflict.
- Kind strings are two-segment (`keyspace.join`) vs the log’s
  documented `<namespace>.<noun>.<verb>`
  (`crates/identikey-log/src/op.rs:31-32`). Design already notes this;
  the standards file should too.
- capability-v1 §1 still lists only auth-challenge under Identity
  (`docs/standards/identikey-capability-v1.md:21`). Restate in the
  keyspace spec; do not patch that table this landing.
