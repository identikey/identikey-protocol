## Verdict

Send-back. Steer is coherent. Three wire facts are still unnamed.
`act` would have to invent them, which is a silent re-steer.

## Steelman against

Keep the packet thin: genesis is “the first op,” admin is “whoever
signs,” P-256 wrap-targets just work. That is how FOKS prose reads.
It fails here because identikey-log already froze the actor as a
32-byte Ed25519 key, and the seven kinds have no birth op. An
independent implementer cannot pick those without forking the log
or minting an eighth kind.

## One real tradeoff

Name genesis as the first `keyspace.join` (no eighth kind, matches
steer’s catalog) versus add `keyspace.genesis`. The first keeps the
seven-kind freeze; it makes “empty keyspace with no members” impossible
by construction. The second allows a PTK with no roster yet. This
landing should pick, not leave both.

## Findings

1. **Genesis kind is unnamed.** Design says the id is the genesis
   `content_hash`. The kind list has no create/genesis. `nest` births
   an inner keyspace; the outer house keyspace has no designated birth
   kind. (`design.md` Wire / Id; `specs/identikey-keyspace/spec.md`
   Requirement: Keyspace identifier, Requirement: Op kinds)

2. **Log actor vs wrap target.** identikey-log `Op.actor` is the raw
   32-byte Ed25519 public key
   (`crates/identikey-log/src/op.rs:12-13,40-41`;
   `crates/identikey-log/src/sign.rs:39,112`). Auth-challenge classical
   keys are Ed25519 **or** P-256
   (`docs/standards/identikey-auth-challenge-v1.md` §3.1). v1 wrap tags
   include `p256-xchacha20poly1305`. The packet never says a P-256-only
   enclave identity cannot author keyspace ops. Either that is a
   stated rule (wrap-target only; admin companion is Ed25519) or this
   change is secretly amending identikey-log.

3. **Admin-ness has no field.** “Admin keys keep it alive” is the
   liveness rule and has no roster encoding. Join/change bodies are
   unspecified. Without a field, every Ed25519 actor who can append
   is an admin, which collapses kick.

## What is solid

- Protocol word `keyspace`, product word `guild` (D5). No `guild.*`.
- Distributed object, not a located document. Log is transport.
- Seven kinds with `leave` distinct; kick/wrap/admin-grant are not
  kinds.
- Self-describing CBOR wrap; no HPKE; no PQ wrap this landing.
- Device cascade named, not specified as objects.
- Two profiles, access-node nested after assign-node.
- Three layers uncollapsed. capability-v1 not modified this landing.
- Living file is `docs/standards/identikey-keyspace-v1.md`. No
  `openspec/specs/` tree. Test-vector hooks, not filled fixtures.
- identikey-log kind strings stay open; body stays opaque CBOR.
  `content_hash` is already `blake3(canonical unsigned envelope bytes)`
  with no domain separation (`crates/identikey-log/src/codec.rs:190-202`).

## Implementer gaps (act, after amend)

- Wrap CBOR map keys (alg, recipient, ciphertext, nonce/epoch).
- Kind strings are two-segment (`keyspace.join`) against the log’s
  documented `<namespace>.<noun>.<verb>` convention
  (`crates/identikey-log/src/op.rs:31-32`). Convention is not enforced;
  the spec should say these are `<namespace>.<verb>`.
- Epoch all-or-none vs concurrent `epoch-begin` (log does not merge).
- RFC 7748 Ed25519→X25519 conversion details (clamping, small-order).
- capability-v1 §1 table still lists only auth-challenge under
  Identity; this spec restates the split and does not patch that table.
